Les bases du développement web

Avant d'écrire une seule ligne de code, il faut comprendre les trois piliers sur lesquels repose n'importe quelle application web.

🏗️

HTML — La structure

HTML décrit le contenu de la page : titres, paragraphes, boutons, formulaires. C'est le squelette.

🎨

CSS — Le style

CSS applique les couleurs, les polices, les marges, les animations. C'est la peau et les habits.

⚡

JavaScript — Le comportement

JavaScript rend la page interactive : réagir aux clics, calculer des totaux, afficher des données. C'est les muscles.

Comment le navigateur affiche une page

Quand tu ouvres une URL dans ton navigateur, voici ce qui se passe :

1

Le navigateur télécharge les fichiers

Il récupère le fichier index.html depuis le serveur, puis tous les fichiers CSS et JavaScript qu'il référence.

2

Il construit l'arbre de la page (le DOM)

Le DOM (Document Object Model) est la représentation interne de la page — une liste de tous les éléments HTML organisés en arbre.

3

Il applique les styles CSS

Chaque élément reçoit sa couleur, sa taille, sa position selon les règles CSS.

4

Il exécute le JavaScript

Le code JavaScript s'exécute, peut modifier le DOM en temps réel, et rend la page interactive.

Application web vs site web traditionnel

🌐 Site traditionnel

À chaque action (clic sur un lien), le navigateur demande une nouvelle page complète au serveur. La page se recharge entièrement.

⚡ Application web (SPA)

Une seule page est chargée au départ. Ensuite, JavaScript met à jour uniquement les parties qui changent, sans rechargement. C'est ce qu'on appelle une SPA (Single Page Application).

Notre application Suivi de Budget est une SPA : tu ajoutes une transaction, et la liste se met à jour instantanément sans recharger la page.

C'est quoi un composant ?

Un composant est un morceau d'interface réutilisable. Imagine des blocs LEGO : chaque bloc (bouton, carte, formulaire) est un composant qu'on assemble pour construire l'interface complète.

Analogie concrète Dans notre app, chaque carte du tableau de bord ("Revenus", "Dépenses", "Solde") est le même composant StatCard utilisé trois fois avec des données différentes.

C'est quoi le localStorage ?

Le localStorage est un petit espace de stockage intégré au navigateur. Il permet à une application web de sauvegarder des données directement sur ton ordinateur, sans serveur. Les données persistent même si tu fermes l'onglet ou redémarres le navigateur.

JavaScript 
// Sauvegarder des données
localStorage.setItem('ma_cle', JSON.stringify(donnees));

// Lire des données
const donnees = JSON.parse(localStorage.getItem('ma_cle'));

// Supprimer
localStorage.removeItem('ma_cle');

Les outils utilisés

Écrire une application moderne nécessite un écosystème d'outils. Voici ceux qu'on a utilisés et pourquoi.

Node.js et npm — Le moteur

Node.js permet d'exécuter du JavaScript en dehors du navigateur, sur ton ordinateur. C'est la fondation de tout l'écosystème de développement web moderne.

npm (Node Package Manager) est le gestionnaire de paquets : il permet d'installer des bibliothèques tierces en une commande.

Terminal 
# Installer une bibliothèque
npm install recharts

# Installer toutes les dépendances d'un projet existant
npm install

React — La bibliothèque d'interface

React (créé par Meta/Facebook) est la bibliothèque la plus populaire pour construire des interfaces. Elle repose sur deux idées clés :

  • Les composants : des fonctions JavaScript qui retournent du HTML
  • Le state (état) : des données qui, quand elles changent, mettent à jour l'affichage automatiquement
React (JSX) 
// Un composant React = une fonction qui retourne du HTML
function Bonjour({ prenom }) {
  return <p>Bonjour, {prenom} !</p>;
}

// On l'utilise comme une balise HTML
<Bonjour prenom="Marie" />
C'est quoi le JSX ? JSX est une syntaxe qui permet d'écrire du HTML directement dans du JavaScript. React le transforme automatiquement en JavaScript pur lors de la compilation.

Vite — L'outil de build

Vite est un outil qui :

  • Lance un serveur de développement ultra-rapide (npm run dev)
  • Recharge automatiquement le navigateur quand tu modifies un fichier (HMR)
  • Compile et optimise ton code pour la production (npm run build)

Recharts — Le graphique

Recharts est une bibliothèque de graphiques pour React. Elle fournit des composants prêts à l'emploi comme PieChart, BarChart, LineChart. On lui passe des données, elle s'occupe du rendu.

React 
import { PieChart, Pie, Cell } from 'recharts';

const donnees = [
  { name: 'Loyer', value: 850 },
  { name: 'Courses', value: 200 },
];

function MonGraphique() {
  return (
    <PieChart width={300} height={300}>
      <Pie data={donnees} dataKey="value" />
    </PieChart>
  );
}

Étape 4 — La logique métier (useTransactions.js)

Dans React, on sépare la logique des données de l'affichage. Un hook est une fonction qui gère la logique et l'état. Notre hook useTransactions gère tout : ajout, suppression, calculs, sauvegarde.

src/hooks/useTransactions.js 
import { useState, useEffect, useMemo } from 'react';

export function useTransactions() {
  // useState : données qui déclenchent un re-rendu quand elles changent
  const [transactions, setTransactions] = useState(() => {
    // Initialisation : lire les données sauvegardées
    const saved = localStorage.getItem('ledger_transactions_v1');
    return saved ? JSON.parse(saved) : [];
  });

  // useEffect : sauvegarder à chaque modification
  useEffect(() => {
    localStorage.setItem('ledger_transactions_v1', JSON.stringify(transactions));
  }, [transactions]); // s'exécute quand "transactions" change

  // useMemo : calculer les totaux uniquement quand la liste change
  const { income, expense } = useMemo(() => {
    return transactions.reduce((acc, t) => {
      if (t.type === 'revenu') acc.income += t.amount;
      else acc.expense += t.amount;
      return acc;
    }, { income: 0, expense: 0 });
  }, [transactions]);

  const addTransaction = (data) => {
    setTransactions(prev => [{ ...data, id: crypto.randomUUID() }, ...prev]);
  };

  const deleteTransaction = (id) => {
    setTransactions(prev => prev.filter(t => t.id !== id));
  };

  return { transactions, addTransaction, deleteTransaction, income, expense };
}
Les trois hooks React fondamentaux
  • useState — stocke une valeur qui peut changer. Quand elle change, React met à jour l'affichage.
  • useEffect — exécute du code en réaction à un changement (ici, sauvegarder dans localStorage).
  • useMemo — met en cache un calcul coûteux et ne le recalcule que si les données sources changent.

Étape 5 — Assembler les composants dans App.jsx

Le composant racine App.jsx appelle le hook pour obtenir les données, puis les distribue aux composants enfants.

src/App.jsx 
import { useTransactions } from './hooks/useTransactions';
import Dashboard from './components/Dashboard';
import TransactionForm from './components/TransactionForm';
import TransactionList from './components/TransactionList';

export default function App() {
  // On récupère tout depuis notre hook
  const { transactions, addTransaction, deleteTransaction,
          income, expense, balance } = useTransactions();

  return (
    <div className="app">
      <Dashboard income={income} expense={expense} balance={balance} />
      <TransactionForm onAdd={addTransaction} />
      <TransactionList transactions={transactions} onDelete={deleteTransaction} />
    </div>
  );
}

Étape 6 — Le formulaire d'ajout (TransactionForm.jsx)

Le formulaire utilise un état local pour gérer ce que l'utilisateur est en train de saisir, puis appelle onAdd quand il soumet.

src/components/TransactionForm.jsx 
import { useState } from 'react';

export default function TransactionForm({ onAdd }) {
  const [type, setType] = useState('revenu');
  const [description, setDescription] = useState('');
  const [amount, setAmount] = useState('');

  const handleSubmit = (e) => {
    e.preventDefault(); // empêche le rechargement de la page
    if (!description || !amount) return;

    onAdd({ type, description, amount: parseFloat(amount) });

    // Réinitialiser le formulaire
    setDescription('');
    setAmount('');
  };

  return (
    <form onSubmit={handleSubmit}>
      <button type="button" onClick={() => setType('revenu')}>Revenu</button>
      <button type="button" onClick={() => setType('depense')}>Dépense</button>
      <input value={description} onChange={e => setDescription(e.target.value)} />
      <input type="number" value={amount} onChange={e => setAmount(e.target.value)} />
      <button type="submit">Ajouter</button>
    </form>
  );
}

Comment ça tient ensemble

App.jsx (possède les données via useTransactions) │ ├── transmet income, expense, balance → Dashboard.jsx (affiche) ├── transmet onAdd → TransactionForm.jsx (collecte) └── transmet transactions, onDelete → TransactionList.jsx (affiche + supprime)
Le flux de données React va dans un seul sens Les données descendent du parent vers les enfants via les props. Les enfants remontent des actions via des fonctions (callbacks). C'est ce qu'on appelle le "one-way data flow".

Conteneuriser l'application avec Docker

La conteneurisation permet d'emballer l'application avec tout ce dont elle a besoin pour fonctionner, et de la lancer identiquement sur n'importe quel ordinateur.

C'est quoi un conteneur ?

Imagine que tu livres l'application dans une boîte hermétique qui contient :

  • Le code compilé de l'application
  • Le serveur web pour la servir
  • Toutes les configurations nécessaires

Cette boîte (le conteneur) fonctionne de la même façon sur tous les systèmes : Windows, Mac, Linux, un serveur cloud. La personne qui reçoit la boîte n'a rien à installer à part Docker.

💻
Ton ordinateur (Mac, Windows, Linux)
Le système hôte — peu importe lequel
🐳
Docker Engine
Le moteur qui fait tourner les conteneurs
📦
Conteneur — nginx:alpine
Un Linux minimaliste avec nginx installé
⚡
Suivi de Budget (fichiers compilés)
Les fichiers HTML/CSS/JS dans /usr/share/nginx/html

C'est quoi une image Docker ?

Un conteneur est une instance en cours d'exécution. Une image est le modèle à partir duquel on crée des conteneurs — comme un moule à gâteau. Le Dockerfile est la recette pour construire l'image.

Le Dockerfile — la recette, ligne par ligne

Notre Dockerfile utilise une technique appelée build multi-stage : deux étapes séparées pour réduire la taille de l'image finale.

Dockerfile 
# ── ÉTAPE 1 : Compiler l'application ─────────────────────
# On part d'une image Node.js officielle (Alpine = version légère)
FROM node:20-alpine AS builder

# On définit où on travaille à l'intérieur du conteneur
WORKDIR /app

# On copie les fichiers de dépendances en premier
# (Docker met en cache cette étape si package.json n'a pas changé)
COPY package.json package-lock.json ./

# On installe les dépendances
RUN npm ci

# On copie tout le reste du code source
COPY . .

# On lance "npm run build" → génère le dossier dist/
RUN npm run build


# ── ÉTAPE 2 : Servir l'application ───────────────────────
# On repart d'une image nginx minimaliste (sans Node.js)
FROM nginx:1.27-alpine AS runner

# On copie UNIQUEMENT les fichiers compilés depuis l'étape 1
# Node.js et node_modules ne sont PAS inclus → image plus légère
COPY --from=builder /app/dist /usr/share/nginx/html

# On remplace la config nginx par défaut par la nôtre
COPY nginx.conf /etc/nginx/conf.d/default.conf

# Le conteneur écoute sur le port 80
EXPOSE 80

# Commande de démarrage
CMD ["nginx", "-g", "daemon off;"]
Pourquoi deux étapes ? Sans multi-stage, l'image finale contiendrait Node.js, npm, et tous les node_modules (~200 Mo). Avec multi-stage, l'image finale ne contient que nginx + les fichiers compilés (~30 Mo). 7 fois plus légère !

Le fichier nginx.conf — le serveur web

Nginx est le serveur web qui répond aux requêtes du navigateur. Notre configuration est minimale mais correcte :

nginx.conf 
server {
    listen 80;           # Écouter sur le port 80
    root /usr/share/nginx/html;  # Dossier des fichiers à servir

    # Compression : réduit la taille des fichiers transférés
    gzip on;
    gzip_types text/plain text/css application/javascript;

    # Cache longue durée pour les assets (JS, CSS, images)
    location ~* \.(js|css|woff2?)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    # SPA : toutes les URLs renvoient index.html
    # (React gère lui-même le routage côté navigateur)
    location / {
        try_files $uri $uri/ /index.html;
    }
}

Le docker-compose.yml — lancer facilement

Taper des commandes Docker longues à chaque fois est fastidieux. docker-compose.yml mémorise la configuration pour qu'on n'ait qu'une commande à taper.

docker-compose.yml 
services:
  suivi-de-budget:
    build: .           # Construire l'image depuis le Dockerfile du dossier actuel
    image: suivi-de-budget:latest  # Nom de l'image créée
    container_name: suivi-de-budget  # Nom du conteneur
    ports:
      - "8080:80"      # Port de ta machine : port du conteneur
    restart: unless-stopped  # Redémarrer automatiquement si plantage

Étapes pour conteneuriser une application

1

Installer Docker Desktop

Télécharge et installe Docker Desktop. Lance-le et attends que l'icône soit verte.

2

Créer le Dockerfile

À la racine de ton projet, crée un fichier nommé exactement Dockerfile (sans extension) avec la recette de construction.

3

Créer le .dockerignore

Comme .gitignore, ce fichier liste ce que Docker doit ignorer lors de la copie du code. Au minimum :

.dockerignore
node_modules
dist
.git
4

Créer le docker-compose.yml

Ce fichier simplifie le lancement. Une fois créé, une seule commande suffit pour tout démarrer.

5

Construire et lancer

Terminal
# Construire l'image et lancer le conteneur
docker compose up --build

# Ouvrir http://localhost:8080 dans le navigateur

# Arrêter
docker compose down
Erreur fréquente : "Cannot connect to the Docker daemon" Docker Desktop n'est pas lancé. Ouvre l'application Docker Desktop sur ton ordinateur et attends que l'icône en bas à droite soit verte avant de retaper la commande.
